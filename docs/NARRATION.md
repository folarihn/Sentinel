# Ninety-second narration and evidence labels

Use genuine UI captures and actual runtime journals. The narration below is 147
words; rehearse it against the final media and keep the finished demonstration
within 90 seconds. It does not require a new model call merely to repeat footage.

> Sentinel OS adds policy and accountability to Hermes tools.
>
> This recorded model task ran in an isolated profile. Hermes executed its
> terminal and file actions; Sentinel evaluated them before execution and kept a
> redacted journal.
>
> Watch shows runtime activity. Every decision has a rule and explanation. Here,
> the real Hermes dispatcher blocked a restricted disposable operation before
> its tool body ran.
>
> Native approval still controls execution. In our human test, the owner approved
> two distinct writes through Hermes' callback. Each changed operation requested
> a fresh decision. Rejection is covered separately by a labeled test fixture;
> we do not present that as a human denial.
>
> Replay reconstructs recorded history without running commands again.
>
> This file change produced a checkpoint. Authorized recovery verifies integrity
> and conflicts before restoring it. External side effects are not reversible here.
>
> Sentinel is a trusted hook layer, not an operating-system sandbox.
>
> Autonomy with accountability.

## On-screen labels and sequence

- **0–12 seconds:** identity and purpose; caption the actual data source.
- **12–30 seconds:** **Recorded real-model execution · isolated profile**. Show
  the recorded task and matching Watch/Replay operations. If a fresh runtime is
  executing during capture, label only that portion **Live host execution**;
  historical events must never be called newly arriving model activity.
- **30–44 seconds:** **Actual Hermes host execution · disposable targets** for
  the blocked operation. If final model-driven restricted attempts are verified,
  the label may identify their actual model evidence instead; do not substitute
  a fabricated or direct-callback trace.
- **44–59 seconds:** **Actual owner approval · native callback/chat bridge**.
  Do not imply that a dashboard approval button or native CLI-button click was
  used. Any displayed denial fixture needs **Fixture human decision** visibly.
- **59–72 seconds:** Replay, exact rule explanation and event correlation.
- **72–84 seconds:** actual checkpoint and restoration outcome, including the
  supported-file boundary. Keep personal paths and tokens out of public captures.
- **84–90 seconds:** final reviewed install/pin information and closing identity.

Use the exact SHA from the final release record. Do not narrate catalog admission,
public availability, a license or a submitted entry until those actions are
actually approved and complete. Keep raw logs, prompts, credentials and personal
paths outside the media. Genuine still-image walkthroughs must be labeled as
such rather than passed off as a continuous live screen recording.
