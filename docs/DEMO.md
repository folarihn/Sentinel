Use only disposable directories and synthetic data. `scripts/demo.py` generates
explicitly labeled fixture activity through the real Sentinel runtime and store;
it must never be presented as a live Hermes session. Its output directory can be
opened with the local dashboard using `--data` and `--workspace`.

For the final under-90-second recording, use an isolated Hermes profile with a
real model connection supplied by the owner, and capture a genuine safe action,
restricted synthetic operation, native approval decision, forensic timeline, and
supported file restoration. Show the exact policy reason. Do not record credentials
or use actual git pushes/deployments/financial operations as demonstrations.

The current host contract test verifies loader and approval-gate behavior with a
fixture decision callback. This is not a replacement for the live final recording.
Final social posting, public visibility, catalog PR and submission require owner
approval under the build directive.
